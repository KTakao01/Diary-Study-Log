# KPI画面実装の学び：仕様・処理・画面表示まで確認する

- 記録日：2026-11-18
- 分類：技術課題への取り組みログ（画面実装の振り返り）

## 振り返りの起点

Claude Codeを使って画面を実装する中で、KPIの指標仕様を作り、バックエンドでどう処理するかまで検討・確認していた。

また、ロバストネス図、ユースケース図、クラス図、ER図、シーケンス図を作成し、細かなレビュー指摘についても考えていた。

それでも、**「そのKPIを画面でどう見せるか」という点の確認が十分ではなかった。**

## 今回の学び

**KPIの定義と処理の検討に加えて、利用者が画面から数値の意味を読み取り、必要な判断ができるかまで確認する。**

設計資料を作成したこと、指標や処理を検討したこと、レビュー指摘を考えたことは、今回実施できていた事項として残す。そのうえで、画面表示の確認を開発の完了条件に含める必要がある。

細かな指摘への検討と、利用者が触れる画面全体の妥当性の確認を、それぞれ行う。改善策を考える際は、今回抜けていた確認を具体化し、実際の画面とデータで確かめる手順を設ける。

以下は、この振り返りを踏まえた次回の改善案として整理する。

## 次回の進め方（優先順位）

1. **利用者の判断を先に書く。** 「誰が、どの場面で、このKPIを見て何を判断するか」を一文にする。
2. **早い段階で画面を具体化する。** ワイヤーフレームや簡単な試作画面に具体的なサンプル値を入れ、表示位置・優先順位・数値／表／グラフの使い分けを確認する。
3. **仕様から表示まで一つの例を通す。** 入力データ、集計結果、APIの返却値、画面上の表示をつなげて、期待した値と意味になっているか照合する。
4. **実際の画面を操作してレビューする。** 通常時に加えて、データがない場合や取得に失敗した場合も確認する。画面レビューで決めた内容を、表示仕様・受入条件へ反映する。

## KPI画面の確認チェックリスト

- [ ] 誰が何を判断するために見る指標かを説明できる。
- [ ] 指標名、単位、集計期間、対象範囲が画面から読み取れる。
- [ ] 重要な指標の優先順位と、数値・表・グラフなどの表示方法が目的に合っている。
- [ ] 目標や前期と比較する場合、比較対象と増減の意味が明確になっている。
- [ ] フィルターや期間変更がある場合、適用範囲と表示結果が一致している。
- [ ] 0件、未取得、計算不能、読込中、取得エラーなど、必要な状態の表示を決めている。
- [ ] サンプルデータを使い、期待値と実際の画面表示を照合している。

## 具体例（説明用の仮の例）

例えば「達成率20%」という表示を確認する場合、計算式の正しさに加えて、何に対する20%か、どの期間・対象の数値か、目標や比較値をどう読み取るかを画面で確かめる。分母が0の場合や、まだデータを取得していない場合の表示も決める。

この例の指標と数値は説明用であり、今回扱った実際のKPIや業務データを示すものではない。

## Claude Codeに依頼するときの確認事項

画面実装を依頼するときは、KPIの定義・処理と併せて、利用者の目的、表示例、各状態の見せ方、確認用データを渡す。未確定の表示仕様は確認事項として明示する。

生成された画面は自分でも開いて操作し、指標の意味と表示が一致しているかを確認する。

## 次回の完了条件

**代表的な利用シナリオと具体的なデータを使って、画面から必要な情報を読み取り、想定した判断ができることを確認できている。**
